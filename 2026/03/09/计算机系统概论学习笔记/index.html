计算机系统概论

为什么大计，计系和数电学的差不多？

前面的基础知识（bit，数据类型，进制转换，逻辑运算）和数电以及计算机导论重复，详情请看数字电路学习笔记 | 暝の窝和深大计算机导论（毛睿）速成笔记 | 暝の窝

整数数据类型

  • 无符号整数：非负数

​ 位值法：每个位置有对应的权值

​ 重：每个介于0~2^k-1之间的数都有唯一的k位编码

  • 有符号整数：正数，0，负数

    有符号整数将2^k个整数一分为二，用以表示正负的区别

    • 符号位表示法：将第一位作为符号表示正负，第一位为0表示负数，为1表示正数

    • 反码表示法：将正数的bit全部取反，如00101（5），反码为11010（-5）

补码

有符号整数不论用哪种方法表示，都会多一位数字，即不应该存在的-0，我们通过补码来排除掉这一可能

补码的正数表示方法和前面两种方法相同，以5bit举例（即32个数字），00000表示0，00001表示1，以此类推，直到01111表示15

负数方面，在反码中，11111表示-0，而补码中表示-1，即补码中负数为对应的反码＋1（-1的反码为11110，要想变为补码，11110+1=11111）

补码的原理是运用二进制加减法得出对应的结果

如6+5=11，即00110+00101=01011

换成减法得到负数的表示方式，即为补码中负数的表示方式

补码完全满足二进制加减法，且加法为取模运算（如11111（-1）加1为100000，第六位不存在，直接去掉，为00000（0））

补码的算术运算

补码中不存在真正意义上的减法，可以理解为正数+负数，在计算减法中，将-正数转换为对应的负数再相加才能得到正确结果

另外，有的时候会遇到不同bit数字之间的加减法，对于此时我们要对数字进行拓展，对于正数，可以在前面加0进行补齐，（00001＝0000000001）；对于负数，则在前面加1进行补齐（11111111011=111111111111111011）

溢出问题

由于一定bit可以表示的数字有限，当相加的数字过大，由于取模运算，导致会输出错误答案

如9＋11=等于20，但是在补码二进制中，由于取模运算，01001+01011=10100，原本110100由于只能取5bit，第一位的1被去掉了，导致输出错误结果

正溢出：正数+正数=负数

负溢出：负数+负数=正数

判断溢出：符号位Cf（最左位）与最高有效数位C（第二左位）不同

位矢量

位矢量是一串二进制数，其中数字对应的为bool值（0——空闲，1——忙碌）

在系统中快速查看某个单元的运行状态

如八个机器0~7，对应从右往左每个bit，位矢量11000010表示1，6，7空闲

浮点数

N=(-1)^s 1.尾数\2^（指数-127） ——小数

浮点数会被正则化，即小数点左边有且仅有1个非零数（十进制），在二进制中，这个数只能为1，所以在IEEE标准中，这个数被省略（只看尾数和正负）

IEEE转换浮点数

-6.625

先转换二进制

-6.625

=-110.101

再正则化

=-1.10101*2^2

=1（符号位） 10000001（指数，占8位，这里为129）10101000000000000000（小数点后数字，补齐23位）

汇编语言（LC-3）

每条指令占16位，数字使用补码表示

条件码：N：小于0，Z：等于0，P：大于0

  • NOT：1001 Dst Src 111111

    对应 Dst=Src取反

    前四位为操作码，三位为目的寄存器，三位为原寄存器，后6位为全1（无实义）

  • ADD：0001 Dst Src1 0 00 Src2 或 0001 Dst Src1 1 Imm5

    对应 Dst数值=Src1数值+Src2数值 或 Src1数值+Imm5数值

    前四位为操作码，三位为目的寄存器，三位为原寄存器1，一位表示使用类型（若该位为0，两位为全0（无实义），三位为原寄存器2；若该位为1，五位为立即数对应补码，数值可为-16~15）

  • AND：0101 Dst Src1 0 00 Src2 或 0001 Dst Src1 1 Imm5

    对应 Dst=Src1*Src2 或 Src1*Imm5（与运算）

    前四位为操作码，三位为目的寄存器，三位为原寄存器1，一位表示使用类型（若该位为0，两位为全0（无实义），三位为原寄存器2；若该位为1，五位为立即数对应补码，数值可为-16~15）

  • LD：0010 Dst PCoffset9

    对应 将输入的数据存储在Dst

    前四位为操作码，三位为目的寄存器，九位为输入的数据对应地址的偏移值，即最终对应地址为当前地址（指令所处地址）+1+偏移值

  • ST：0011 Src PCoffset9

    对应 将Src的数据取出

    前四位为操作码，三位为原寄存器，九位为输出的数据对应地址的偏移值，即最终对应地址为当前地址（指令所处地址）+1+偏移值

  • LDI：1010 Dst PCoffset9

    对应 将输入的数据存储在Dst

    前四位为操作码，三位为目的寄存器，九位为输入的数据对应地址的地址的偏移值，即输入数据对应地址的地址为当前地址（指令所处地址）+1+偏移值，读取其中的地址并访问，得到输入数据

  • STI：1011 Src PCoffset9

    对应 将Src的数据取出

    前四位为操作码，三位为原寄存器，九位为输出的数据对应地址的地址的偏移值，即输出数据对应地址的地址为当前地址（指令所处地址）+1+偏移值，读取其中的地址并访问，将输出数据存入其中

  • LDR：0110 Dst Base offset6

    对应 将输入的数据存储在Dst

    前四位为操作码，三位为目的寄存器，三位为基址寄存器（存储一个地址），六位为输入的数据对应地址的偏移值，即最终对应的地址为基址+偏移值

  • STR：0111 Src Base offset6

    对应 将Src的数据取出

    前四位为操作码，三位为原寄存器，三位为基址寄存器，六位为输出的数据对应地址的偏移值，即最终对应的地址为基址+偏移值

  • LEA：1110 Dst PCoffset9

    对应 将输入的地址存储在Dst

    前四位为操作码，三位为目的寄存器，九位为输入地址的偏移值，即最终对应地址为当前地址（指令所处地址）+1+偏移值

  • BR：0000 n z p PCoffset9

    对应 判断上一条指令的结果对n，z，p是否成立，有一个成立就会跳转到输入的指令

    前四位为操作码，三位分别为条件码NZP（若NZP=111，表示无条件跳转），九位为跳转指令对应地址的偏移值，即最终对应地址为当前地址（指令所处地址）+1+偏移值

  • JMP：1100 000 Base 000000

    对应 直接跳转到输入的指令

    前四位为操作码，三位为全0（无实义），三位为基址寄存器，六位为全0（无实义）

  • TRAP：1111 0000 trapvect8

    对应 直接跳转到对应的trap子程序，调用系统功能，如OUT，HALT

    前四位为操作码，四位为全0（无实义），八位为陷阱向量，指向对应的功能

  • JSR：0100 1 PCoffset11

    对应 跳转到对应的子程序

    前四位为操作码，一位为1，11位为跳转指令对应地址的偏移值，即最终对应地址为当前地址（指令所处地址）+1+偏移值

  • JSRR:0100 0 00 Base 000000

    对应 跳转到对应的子程序

    前四位为操作码，三位为0，三位为地址寄存器（子程序所在地址），六位为0

标号

在汇编语言中可以通过标号指向一个内存单元（可以对应cpp中的变量），标号可以用来作为存储常量（使用LD等进行访问），也可以作为跳转指令的目标

伪操作

给汇编器执行的指令

  • .ORIG - 指示程序起始地址

  • .END - 指示程序主代码在此结束（不是停止程序）

  • .BLKW - 分配n个元素的内存单元空间（只分配不设值）

  • .FILL - 分配1个元素的内存单元空间并赋值

  • .STRINGZ - 定义一个字符串，占用n+1个内存单元（字符串结尾“\0”）

Trap指令

LC3提供的伪指令，调用快捷功能（不需要使用TRAP，直接调用对应的系统功能）

  • GETC - 从键盘读入一个字符，其ASCII码存入R0（高八位清零，低八位存数据）
  • OUT - 将R0[7:0]（低八位）的字符在屏幕上显示
  • PUTS - 在屏幕上显示一个字符串，起始位置由R0决定，遇到x0000时停止
  • IN - 先显示提示在屏幕上，然后从键盘读入一个字符，将该字符回显在屏幕上，其ASCII码存入R0高八位清零，低八位存数据）
  • PUTSP - 在屏幕上显示一个字符串，但每个单元存两个字符，先输入低八位，再输出高八位，起始位置由R0决定，遇到x0000时停止
  • HALT - 停止执行，输出信息

汇编过程

进行两次扫描，第一次创建符号表，第二次对照符号表进行运行，转换成机器指令（二进制）

符号表：将所有代码中涉及的标号及其地址进行记录

子程序

自己编写的子程序，相当于函数体，使用JSR或JSRR调用，直接在子程序开头加上子程序名，如果需要返回（不是继续运行）需要在结尾使用RET

在子程序中使用的寄存器，要先保存其中数据，运行完子程序之后再将其恢复（除非是需要子程序处理的数据）
